# Cytophage v6 — автономная эволюционная экосистема

Сервер Node.js 22+, без обязательных npm-зависимостей. GitHub Pages показывает интерфейс; **симуляция выполняется на сервере Render**.

## Что изменено

- Новый мир начинается с **двух индивидуальных основательниц** двух разных видов (Люминаты и Ферроксы).
- Матки, собиратели, разведчики, защитники и воины; генетика, мутации, интеллект, возраст, голод, здоровье, названия и события.
- Собиратели находят пищу по координатам, взаимодействуют с ней после физического контакта, приносят запас матке. Без фиксированных круговых зон колоний.
- При `SIM_SPEED=1` первая возможная особь у матки появляется не раньше 10 минут после запуска мира; затем не чаще раза в 3600 секунд модельного времени на матку, при достаточном здоровье, питании и запасах.
- Карта 26 000 × 26 000; новая колония создаётся при достаточном числе особей, общих ресурсах и знаниях.
- Снимок сохраняется каждые 30 секунд, в файл и, если настроен, в Supabase. Клиент получает `/state` примерно каждые 2 секунды.

**Важно:** социальные матки и роль воинов — научно-фантастические игровые механики, а не буквальная биология всех бактерий. Это основа для дальнейшей эволюции механики.

## Как опубликовать

1. **До обновления сделайте резервную копию** действующего мира: v6 при загрузке сохранения v5 сознательно создаёт новый мир из двух бактерий и при следующем сохранении перезаписывает старое состояние. Автоматического отката нет. Скопируйте старый `payload` из Supabase (если используется).
2. Загрузите содержимое этого архива **в корень** репозитория `BALCETUL/Cytophage`, с заменой старых `index.html`, `server.js`, `simulation.js` и остального.
3. В Render укажите этот GitHub-репозиторий, `Build Command` пустой или `npm install`, `Start Command` = `npm start`, Node.js 22+. После деплоя `/health` и `/state` должны отвечать JSON.
4. Если репозиторий используется через GitHub Pages, убедитесь, что Pages публикует ветку с обновлённым `index.html`. Интерфейс в GitHub Pages обращается к `https://cytophage.onrender.com`; если фактический адрес отличается, поменяйте константу `API` в `index.html`.
5. Для постоянного хранения выполните `storage-setup.sql` в Supabase SQL Editor и задайте **только в Render Environment** переменные `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`. Никогда не загружайте настоящий `service_role` в GitHub.
6. При обычной скорости оставьте `SIM_SPEED=1` (можно не задавать). `SIM_SPEED=10` означает ускорение всей симуляции в 10 раз, а не отдельное увеличение рождаемости.

## Render Free — ограничения

Бесплатный сервер Render может засыпать, останавливаться и перезапускаться. Самопинг **не гарантирует** непрерывную работу. Сохранение в Supabase позволяет восстановить последнее записанное состояние, но **события, произошедшие во время сна, не рассчитываются задним числом**. При недоступности Supabase и настроенном удалённом хранении сервер не должен запускать новый пустой мир вместо сохранённого.

## Запуск локально

```sh
node --version # >= 22
npm test
npm start
# http://localhost:3000
```

Для проверки долгих процессов без 24-часового ожидания: `npm run soak`. Этот тест прогоняет 24 часа модельного времени в памяти, не обращаясь к реальному серверу.

## Основные файлы

- `simulation.js` — независимая модель мира, псевдослучайность, питание, размножение, поведение.
- `server.js` — HTTP API, тики модели, сохранение, самопинг.
- `storage.js` / `storage-setup.sql` — долговременные снимки Supabase.
- `index.html` — клиентская карта и статистика.
- `tests/` — тесты физического поглощения пищи, восстановления и ограниченной рождаемости.

### Известные границы v6

Это базовая игровая экосистема. Пока не реализованы сложная тактика войск, переговоры между колониями, построение гнёзд, сезонность, полноценная биохимия, развитое дерево мутаций и полноценный визуальный интерфейс для мобильных боковых панелей. Приоритет отдан целостности серверной модели и старту с двух особей.
